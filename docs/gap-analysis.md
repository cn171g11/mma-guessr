# 与真实「图寻」的差距分析

> 结论先行: 核心玩法 (单机猜图 + 每日挑战 + 多人对战) 已完成并逐字节保持前端兼容, 差距集中在**社交/竞技长线玩法**与**生态化**层面. 本文档列出差距项与建议路线, 供后续阶段排期.

## 一、当前已实现 (对标图寻核心)

- 单机猜图: 全球题库随机 / 区域模式 / 难度过滤, 服务端权威计分 (`5000*e^(-10*max(d,dMin)/(refSpan*α))`)
- 每日挑战: 每日固定 10 题, 服务端权威结算, 每日仅一次, 惰性抽题 + 重建自愈
- 多人对战: 1v1 匹配 (queue → matched → 5 rounds → finished), 服务端计分与落库, Engine.IO v4 polling 与前端 socket.io 4.8.1 字节兼容
- 账号体系: 注册/登录/游客/邮箱验证码/刷新令牌, 成就 (14 项) + 称号, 个人统计, 排行榜 (总榜/日榜)
- 安全: 请求签名 + nonce 防重放, JWT 短时效, 登录锁定, 分级限频, CORS 白名单, SSRF 防护, 指标鉴权

## 二、与真实图寻的差距

### 1. 好友与私房对战 (P1 高价值)

图寻支持好友列表与"开房对战" (邀请码/链接直邀), 当前只有随机匹配, 无法指定对手.

- 建议: 新增 `friends` 表 + 好友申请/同意; 房间支持 `private` 模式, 生成邀请码, 好友凭码加入
- 涉及: `internal/multiplayer` 房间状态机 + 新 `/api/friends` 路由 + 前端好友/邀请 UI

### 2. 天梯排位与段位 (P2)

图寻有赛季排位 (段位/分数/晋级动画), 当前排行榜只是总成绩静态排名, 无竞技段位概念.

- 建议: `season_ratings` 表 (玩家 × 赛季, ELO/积分 + 段位), 赛季结算保留历史段位
- 涉及: 新 `internal/ratings` 包 + 排行榜页段位展示

### 3. 对局轨迹回放 (P2)

图寻对局结束可回放猜图轨迹 (标记→答案移动轨迹). 当前已存 guess/answer 坐标, 数据齐备, 缺回放前端.

- 建议: `/api/games/:id` 返回完整 rounds (坐标已在库), 前端用地图动画回放
- 涉及: 前端 `game.js`/结果页 + 1 个查询接口, 后端改动极小

### 4. 连胜挑战与成就扩展 (P2)

图寻有"连胜"与更丰富的成就/称号系统, 当前成就 14 项为静态定义.

- 建议: 新增连胜场次/连续答对/地区专家等成就项, 成就定义表化 (从代码常量改为 `achievements` 表, 便于扩展)
- 涉及: `internal/achievements` 定义表化 + 解锁判定扩展

### 5. 图包工坊 / 自定义题库 (P3)

图寻支持玩家自制图包并发布/订阅. 当前题库为内置静态数据 (data.js seed).

- 建议: `packs` + `pack_locations` 表, 图包审核/订阅/计分隔离; 属于较大生态功能, 建议排在最后

### 6. 每日挑战计分排行 (P3)

图寻每日挑战有独立排名 (当天最快/最高分). 当前 daily_submissions 仅记录完成, 无每日榜.

- 建议: `daily_scores` 按日聚合, 复用排行榜缓存链路 (daily 前缀已有)
- 涉及: 后端 leaderboard 增加 daily 计分维度 + 前端每日页展示

### 7. 第三方登录 (P3)

图寻支持微信/Google 等第三方登录, 降低注册门槛. 当前仅邮箱注册.

- 建议: 新增 OAuth 表 + 回调路由; 注意回调地址白名单与 state 防 CSRF

### 8. 冷知识 / 地点图鉴 (P3)

图寻答对后展示地点冷知识与收集图鉴 (去过的地点/国家).

- 建议: 新增 `location_facts` 表 + 图鉴页 (基于已有 games 记录统计已答对地点)

## 三、建议路线

| 阶段 | 内容 | 优先级 |
| --- | --- | --- |
| 1 | 好友 + 私房对战 (开房邀请码) | P1 |
| 2 | 对局轨迹回放 (数据已具备) | P2 |
| 3 | 连胜/成就扩展 (定义表化) | P2 |
| 4 | 天梯排位与段位 (赛季) | P2 |
| 5 | 每日挑战计分榜 | P3 |
| 6 | 冷知识图鉴 | P3 |
| 7 | 第三方登录 | P3 |
| 8 | 图包工坊 | P3 |

## 四、技术可行性备注

- SQLite 单文件 + WAL 已支撑上述扩展 (好友/排位/图包均为普通关系表), 无需引入 Redis/PostgreSQL
- 多人私房只需扩展现有 Engine.IO 房间状态机 (增加 `private` 字段与邀请码), 传输层不变
- 轨迹回放所需坐标数据已存于 `game_rounds`, 零后端成本即可落地
- 所有扩展均需保持 `/api` 契约与 socket 事件形状不破坏现有前端 (api.md 契约为准)
